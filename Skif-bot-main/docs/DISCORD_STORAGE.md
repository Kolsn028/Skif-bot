# Логи и копии

Два канала в категории управления: «логи-бота» и «данные-бота».
Их видят Хай, Дэп Овнер, Овнер и владелец/администраторы Discord.
Рекрутам доступ не выдаётся.

Копия содержит настройки, анкеты и решения, статистику рекрутов, дела,
отчёты, контракты, отпуска, МП, основной/резервный состав и подтверждения.
Каждый сервер получает только свои строки. Токены не включаются.
Скриншоты остаются в исходных сообщениях Discord; копия сохраняет ссылки,
а не сами изображения. Удаление исходных сообщений может лишить их доступности.

После изменения базы запись ставится в очередь. Последовательные изменения
объединяются в течение 3 секунд; ошибки повторяются по таймеру до 60 секунд.
При недоступном Discord несохранённые изменения остаются только локально.
Поэтому перед деплоем или перезапуском Хай или старшие выполняют /backup_now
и ждут подтверждения. Нет гарантии нулевой потери данных между последним
подтверждённым сохранением и внезапным завершением процесса.

## Обнаружение каналов

Без переменной бот ищет каналы по технической метке в topic, без учёта имени.
С переменной `DISCORD_BACKUP_CHANNEL_IDS` (JSON вида `{"<guild_id>": <channel_id>}`)
бот дополнительно обнаруживает удаление ожидаемого канала и останавливает запуск
вместо создания пустых данных. Дубли каналов, ошибки целостности и конфликты ID
не замалчиваются. Читается последняя корректная копия среди 50 последних
сообщений канала. Старые копии не удаляются.
Лимит одной копии: 64 МБ JSON и 8 МБ сжатого файла.

## Восстановление

При старте бот проверяет каждый сервер: если локальной конфигурации нет,
а канал с технической меткой backup существует, данные восстанавливаются
из последней проверенной копии (контрольная сумма SHA-256). Существующие
локальные записи снимком из Discord никогда не перезаписываются.

## Отпуск

Новые отпуска добавляют только роль «Отдых». Возврат снимает только роль,
сохранённую при одобрении, даже если её привязка позднее изменилась.
Остальные роли сохраняются.
